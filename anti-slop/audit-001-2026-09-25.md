# Anti-Slop Audit 001: Overview

Date: 2026-09-25  
Mode: audit only. No application code was changed.

## Scope and current state

Inspected the running Ground Console at `http://127.0.0.1:8787/` in dark theme at 1366 × 768 and 390 × 844 CSS px. The local view has no fresh Data Out snapshot: DATA is loading, DoA is unavailable, delivery is blocked, and the map uses the fallback station coordinate. No live RF or telemetry quality was assessed.

## Findings

### A-001 — HIGH: Center button blocks MapLibre Zoom out

Rules: R-26 (interactive elements), R-03 (mobile usability).

The custom `Center` control overlaps the MapLibre `Zoom out` button. At 390 px, their boxes intersect by approximately 39 × 42 px; at 1366 px they intersect by the same amount. A hit test inside the overlap resolves to `Center`, leaving `Zoom out` visually and functionally covered. `TacticalMap.tsx:311` adds the reset button; `styles.css:102` positions it at `top: 52px`; `console-design.css:162` places it above the map controls.

Recommended direction: put `Center` in a non-overlapping control slot and verify hit targets at both narrow and desktop widths.

### A-002 — HIGH: Expanded overlay settings collide with the map HUD

Rules: R-03 (layout collision), R-26 (usable controls).

The settings panel and pinned bottom HUD occupy the same part of the map. At 1366 × 768, the expanded panel spans x=377–767, y=309–753; the bottom legend/coordinate HUD spans x=261–767, y=677–755. That is a 390 × 75 px intersection. The screenshot shows the station-reference card and legend visually running across the lower settings area. At 390 × 844, the panel is about 336 × 445 px inside a 356 × 490 px map, so it dominates the map while the map's other overlays remain present. Relevant rules are `console-design.css:108`, `:118`, and `:332–335`; the HUD markup is `TacticalMap.tsx:305–307`.

Recommended direction: separate the settings surface from the pinned map HUD. For example, suppress/reflow the bottom HUD while settings are open, or move the settings into a panel outside the map canvas. Keep all controls reachable and legible.

### A-003 — LOW: Mobile Overview puts the map below the long plot panel

Rules: R-05 and C-3 (content-driven hierarchy).

At 390 × 844, the Overview shell and status strip end at y=414, the intro ends at y=557, and the polar panel starts at y=571 and is 1,099 px tall. The map panel does not begin until y=1,690, roughly two viewport heights below the page top. The map is therefore absent from the initial mobile view; the polar chart and its controls appear first. The order is set by `console-design.css:293–297`, including `.polar-panel { order: -1; }`.

Recommended direction: put the map first on narrow screens, or give Map and Polar explicit compact views with the map selected by default. Reduce above-the-fold status chrome only where it does not hide freshness or publication state.

### A-004 — LOW: Route focus makes the page title look selected

Rules: C-1 and R-31 (intentional visual decisions).

On initial navigation, `App.tsx:366–378` programmatically focuses the `h1`. The title then receives the same bright rectangular amber outline as a keyboard-focused control via `console-design.css:242`. The outline is visible in the initial mobile capture and reads like an input selection rather than page orientation.

Recommended direction: preserve route focus for keyboard and assistive-technology users, but distinguish the heading's focus treatment from control focus and verify it with keyboard navigation.
