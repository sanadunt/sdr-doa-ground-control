# Audit UI 007: tampilan desktop, tablet dan HP (Ground Console 3.11.0)

- Tanggal: 2026-11-03
- Cabang: `claude/compact-touch-layout` (rilis 3.11.0, commit `918ffef`)
- Mode antislop: 2 (audit setelah jadi). Belum ada yang diubah; nomor yang disetujui pemilik yang dikerjakan.

## Cakupan dan metode

- 178 screenshot dari console nyata (loopback 127.0.0.1:18787 dan LAN view) dengan edge MQTT tiruan dan Mock SDR: desktop 1920, 1440, 1280, 1024 dan 900 px; tablet 1280x800, 800x1280, 1024x768, 768x1024; HP 915x412, 412x915, 360x740; tema gelap dan terang; ID dan EN; layout compact paksa di halaman groundstation; keadaan tanpa telemetri dan DoA ditahan; menu halaman, checklist Publikasi, menu basemap, Atur, penanda, pindai lebar, konfirmasi Restart, workspace Receiver, Records; 45 tekan Tab untuk fokus keyboard.
- Per screenshot juga diukur dari DOM: teks terpotong atau tertutup, target sentuh, tumpang tindih, kontras WCAG, em dash, overflow horizontal.
- 14 auditor (13 per kelompok layar dan halaman, 1 untuk teks EN/ID) menghasilkan 147 temuan mentah yang digabung menjadi 87; critic kelengkapan menambah 8. Setiap temuan diperiksa verifikator yang tugasnya menyanggah: 91 dari 95 lolos, 2 disanggah, 2 ternyata keputusan pemilik.
- Keputusan pemilik yang tidak dihitung sebagai temuan: layout compact menyembunyikan Polar, Atur, follow-node, pilihan mode dan Kirim; overlay DoA ditahan tetap berwarna penuh; kode status tidak diterjemahkan; "—" sebagai placeholder nilai; PERLU DISIAPKAN dan UNVERIFIED sebagai batas observasi; LAN view hanya baca; tanpa tooltip penjelasan; perilaku notice REFERENSI kompas (ditunda).
- Prioritas mengikuti tier antislop: Hard Gate = TINGGI, Purpose-Gate = SEDANG, Quality Lock = RENDAH. Rincian bukti, penyebab dan perbaikan di bawah tiap temuan adalah catatan verifikator dalam bahasa Inggris, dengan file:baris di kode sekarang.

## Tidak dihitung

- F57 Simulation cards in one row end at three different heights: intended. The screenshot does show Kontrol, Skenario and Pratinjau ending at different heights. But `align-items: start` is the page kit's deliberate rule, and frontend/src/pages/configuration.css:22-24 documents why: 'stacks its cards at their own height, so no card stretches to a taller neighbour and leaves an empty band above its actions'. Stretching Skenario would leave an empty band under its Terapkan button. No content or control is hidden, so this is a design choice, not a defect.
- F64 English jargon in Indonesian dashboard labels ('span', 'frame', 'Sorotan beam', 'Garis bearing', 'Heading RDF-SDR'): false_positive. The screenshot does show 'Sorotan beam', 'Garis bearing', 'Heading RDF-SDR' and 'span 2.0 MHz · frame 89 ms'. But these RF/DoA terms are kept in English on purpose and used the same way across the whole ID dictionary: after line 1000 of i18n.ts, 'bearing' appears 29 times, 'frame' 24 times, 'heading' 7 times, 'span' 5 times and 'beam' 3 times. Examples are 'polar.offsetNodeHeading': 'heading RDF-SDR' and 'mirror.kioskHidden': '...frame berhenti'. The finding's own expected outcome allows 'jargon kept deliberately and the same everywhere', and that is the case here. 'Sorotan beam' is not a doubled noun; it translates 'Beam highlight' (sorotan = highlight). Nothing is mixed in a way that hides meaning, and no rule is broken.
- F72 Latitude/Longitude (and Bearing) left in English on the ID Configuration and Simulation pages: false_positive. The Simulation screenshot does show 'Bearing', 'Latitude' and 'Longitude' in the ID UI. This is consistent terminology across the whole ID dictionary, not a missed translation. 'Bearing' is kept in Indonesian everywhere: map.legendBearing, overlay.bearing, map.hoverBearing, polar.hoverCompass and map.popupBearing ('Bearing DoA'). 'Lintang' and 'Bujur' appear nowhere in i18n.ts, and the ID validation sentences are fully Indonesian with the loanword as the term ('Latitude harus berupa angka.'). Latitude and longitude are standard loanwords in Indonesian GIS and navigation usage. The 'Posisi' label is a different concept (the combined position), not an inconsistent translation of these fields. Changing only these keys would make the ID text less consistent, not more.
- C07 System Health ADC tile shows the raw MQTT topic 'health/detail' as its source: intended. The screenshot does show 'health/detail' under ADC PASS. That label is a deliberate choice, though. The doc comment on overdriveSourceFile() reads 'Name the Data Out file or MQTT topic that reported the ADC state, not the collector's internal source id', so the function was written to print source names: status.json, doa.xml and health/detail. The same row follows that convention: SNR's sub is 'XML' and PAPR's is 'CSV / XML' (:408-409, both source names). The finding says the other subs are operator words, but only DAQ's '0 frame hilang' is. The LoRa rule in CLAUDE.md forbids naming Data Out, settings.json or PPP. health/detail is the edge's own MQTT topic, so that rule does not cover it. This is a documented source-naming convention, not a defect.
